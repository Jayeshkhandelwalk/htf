# AI-based protein detection system for agricultural by-products

For your project, you can build an AI-powered protein estimation system that analyses guar meal, groundnut cake, almond cake, rice bran and pulse-processing residues, then predicts their protein content.

The most practical approach is to combine Near-Infrared (NIR) spectroscopy + machine learning + laboratory-verified protein measurements.

The important distinction is that AI does not directly know how much protein is in a sample. You first need samples whose protein content has been measured in a laboratory. The model learns patterns in the sensor data that correlate with those measurements and predicts protein content for new samples.

## 2. Hardware required

There are two possible builds: a proper research prototype and a low-cost demonstration.

[NeoSpectra | Instant Lab Analysis Solutions Where Decisions Matter](https://images.openai.com/static-rsc-4/QgRYhVkptcvwjtAADoMvYjE4MAsrDuN4oIqJYtB6wH9mkIOWDQcEs2LNLkq3vJIBU8bT88mMHk1-wh1-rxHim69lIe3TsbgiXIFCHnmqwJaEqOOygcRZdVDFsxVJ7Cvng60eIcHbS4QFut_8g1GfCoVhI8h9tAG2vWz-1ue7OQs?purpose=inline)

Option A — Recommended: NIR-based AI

Best for real predictions

- Portable NIR spectrometer with a suitable wavelength range, ideally extending into the short-wave NIR region around 900–1700 nm or beyond.
- Sample cup or holder and a consistent sample preparation setup.
- Laptop to process sensor data and run the model.
- Access to a food-analysis laboratory for reference protein measurements.

A commercial NIR instrument is the easiest route to reliable spectral data.

[Newton Creative Labs — Product Development & Innovation](https://images.openai.com/static-rsc-4/u5UTnJfuKWpgzyvM_XC9Fyq4mnv9fCHXxwteAStNgG2vr-ei6N3PFaUEx9PHygQ-nLPxTAoSmGNXCLOPhCcvNaj72UpS-R46TTW0ncdUUfVWHWQALMimLFjgwV6IxVKgd3G_z6WJxDYLQKbBSLxFAGVTsGZAtVSM1W-jUc2_mk0?purpose=inline)

Option B — Low-cost prototype

- ESP32 or Arduino for sensor control.
- A suitable miniature spectrometer module, if available within budget.
- Laptop for model training and inference.
- Sample container, consistent illumination and calibration references.

A simple colour sensor or ordinary camera cannot reliably measure protein percentage. This build is useful for demonstrating data acquisition, but it needs a validated spectroscopy sensor and calibration dataset for meaningful protein predictions.

Important: You do not need a powerful GPU. A normal laptop can train and run models such as Partial Least Squares Regression (PLSR) and Random Forest on typical spectroscopy datasets.

Research has demonstrated protein estimation from NIR spectra in grains and other plant materials, but calibration performance depends on the sample types and the instrument used.&#x20;

## 3. Software stack

Here is the stack I would use for a student or college project.

| Layer                | Recommended technology                        | Purpose                                                |
| -------------------- | --------------------------------------------- | ------------------------------------------------------ |
| Sensor acquisition   | Spectrometer SDK / Python                     | Read wavelength and intensity data                     |
| Data processing      | NumPy, pandas, SciPy                          | Clean and organise spectra                             |
| Signal preprocessing | Standard Normal Variate (SNV), Savitzky–Golay | Reduce scattering and spectral noise where appropriate |
| AI / ML              | scikit-learn                                  | Train protein prediction models                        |
| Initial model        | PLS Regression                                | Strong baseline for spectroscopy                       |
| Comparison model     | Random Forest or SVR                          | Compare alternative prediction approaches              |
| Model evaluation     | RMSE, MAE, \\(R^2\\)                          | Measure prediction accuracy                            |
| Backend              | FastAPI                                       | Accept sample data and return predictions              |
| Frontend             | HTML, CSS, JavaScript                         | Show results and charts                                |
| Storage              | CSV initially; SQLite later                   | Store sample IDs, readings and lab results             |
| Deployment           | Local laptop initially                        | Run without needing cloud infrastructure               |

Start with PLS Regression rather than a deep neural network. Spectral data are high-dimensional, and a well-calibrated classical model can be more practical when the dataset is small.&#x20;

The laboratory reference measurement is essential during model development. Once validated, the system can estimate protein for new samples without running a laboratory test for every individual prediction. This is the standard calibration approach for NIR analysis.&#x20;

## 5. How much data do you need?

For a student prototype, I would aim for the following initial plan. These are project targets, not guaranteed minimums for scientific validity.

| Dataset component                     | Suggested starting target |
| ------------------------------------- | ------------------------- |
| Total independently collected samples | 150–300                   |
| Different by-product categories       | 5                         |
| Samples per category                  | 30–60                     |
| Reference protein measurements        | Every sample              |
| Independent test samples              | 20% of dataset            |
| Repeated sensor scans                 | 3 per sample, averaged    |

Try to collect samples from different suppliers, production batches and dates. Three scans of the same physical sample are not three independent samples. Split the data by sample or batch to prevent data leakage.

Important modelling decision: With limited data, build a separate calibrated model for each by-product type first. A single model covering all five materials may struggle because their fibre, fat, moisture and spectral properties differ substantially. Test a combined model later.

### Suggested development phases

1. Phase 1: Collect samples and obtain laboratory protein measurements.
2. Phase 2: Borrow or access an NIR spectrometer through a food technology, chemistry or agricultural research lab.
3. Phase 3: Train and compare PLSR, SVR and Random Forest in Python.
4. Phase 4: Validate predictions on samples from unseen batches.
5. Phase 5: Build the dashboard and connect it to the sensor and model.

If you do not yet have access to a spectrometer, you can develop and test the machine-learning pipeline with a properly labelled spectral dataset first. It would be a software prototype, not yet a working physical protein detector.

## My recommendation

Build a portable NIR + Python/PLSR prototype first. It is more defensible scientifically than trying to infer protein from an ordinary camera image, and it leaves room to add anti-nutrient screening and food-suitability analysis later.

For further reading, see the research on [portable NIR for grain protein estimation](https://pmc.ncbi.nlm.nih.gov/articles/PMC9146900/?utm_source=chatgpt.com) and the [Cereals & Grains Association's NIR calibration guidance](https://www.cerealsgrains.org/resources/Methods/Pages/39InfraredAnalysis.aspx?utm_source=chatgpt.com).
